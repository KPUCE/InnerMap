# 01 설계 노트 — #9 (Ⅹ장 재료 후속)

## 방위 계산 위치 — 서버 배제, 기기 내 순수 엔진 (저자 채택 c안)
- "12시=폰 위쪽"은 사용자 heading 없이는 정의 불가, heading은 기기 나침반에만 있음 → 서버 계산은 원천 불가(N-05 경계와 정합).
- 기각 (a) 화면에 직접 계산: #14에서 재분리 비용, 테스트 어려움. 기각 (b) 거리만: AC(시계 방위 환산) 미충족.
- 채택 (c): 값만 받는 순수 함수 엔진 — "방위 검증은 단위 테스트 수준"(AC)을 그대로 실현, #14가 재사용.

## 상세 엔드포인트 신설 vs 검색 응답 확장
- 검색 응답에 lat/lng·aliases를 끼워 넣는 안 기각: 목록 응답이 무거워지고, 상세는 별도 자원이 자연스러움(CLAUDE.md 예시 경로 `/api/buildings/{id}/aliases`와 같은 계층).
- 미게시 404(존재 은닉)는 R-12b의 보수적 해석 — 200+빈 응답, 403 대안 기각(존재 사실 자체가 노출).

## ADR 신설 여부 — 하지 않음
- 방위 산출의 틀은 ADR-005가 이미 결정(보정 계층·±30°·생략 모드). #9는 그 축소 적용이라 새 ADR 없이 ADR-005를 인용. 축소 범위(보정 안내·평활화 제외)는 design.md에 명시.

## 문턱·경계 수치의 출처
- ±30° 게이트: N-04(시계 한 칸). 반개구간 [중심-15°, +15°): 중심 대칭 반올림 — 수학적 관례, '팀 추정' 아님. CLHeading 무효값(-1) 처리: Apple 문서(headingAccuracy < 0 = invalid).
