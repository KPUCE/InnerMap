# ADR-006 게시 건물 조회: 서버 응답 캐시 도입
상태: 채택 (ⅩⅣ장, 2026-07) · 레드팀 RT3 회수
맥락: Ⅵ장 레드팀은 학기 초 조회 폭주 시의 DB 병목(RT3)을 찾고도 백로그로 분류하며 N-03(브리핑 첫 안내 p95 1초)을 관찰 트리거로 삼았다. 설계 문서의 트래픽 가정은 평시 기준이었다. 개강 첫 주 저녁 오리엔테이션 시간대에 요청이 몰리며 게시 건물 조회 p95가 8초까지 올라 N-03을 위반했고, 기기 캐시(R-12c) 유효 기간의 임시 연장으로 완화했다.
결정: 게시 상태 건물 데이터의 조회 응답에 서버 측 캐시를 둔다. 키는 격자 좌표와 반경 밴드, 무효화는 게시 상태 전이(R-12b) 시점에 해당 격자만 수행한다. 관측 항목에 캐시 적중률과 조회 API p95를 상설로 올린다.
근거: ① 읽기가 압도적이고 쓰기는 검수·게시 시점에만 일어난다 ② 트리거로 정해 둔 N-03이 실제로 울렸고, 조건부 항목의 회수는 백로그에 남긴 약속을 지키는 일이다 ③ 기기 캐시는 이미 방문한 지역만 보호하는데 개강 주의 요청은 처음 온 사용자에게서 나왔다.
배제한 대안: 서버 인스턴스 증설(무료 티어 밖·학기 예산 초과, 읽기 편중 부하에는 캐시가 더 싸다), 완화책의 영구화인 기기 캐시 상시 연장(검수로 고쳐진 건물 정보가 늦게 도착), 개강 주 결과 수 제한(브리핑이 얇아지는 증상 억제).
트레이드오프: 검수·게시(E3) 흐름에 캐시 무효화가 완료 조건으로 붙는다. 후속 작업으로 부하 회귀 테스트 추가와 개강 주 알림 문턱 조정이 남고, 설계 문서 레드팀 절의 RT3 분류를 '대응 완료(ADR-006)'로 갱신해야 한다.
