# 파이프라인 이해 검증 (패턴 3 — 역방향 설명)

Sprint 0 완료 조건: 팀원 각자가 아래 스텝 하나씩을 팀에게 설명한다(실습 8 ④·검증 체크리스트 5번).

## 스텝별 "무엇을, 왜"

| 잡 | 무엇을 | 왜 |
|---|---|---|
| changes | PR이 건드린 경로를 감지해 출력 변수로 | 모노레포에서 무관한 구역의 검사를 돌리지 않기 위해. 워크플로우 수준 paths 필터를 쓰지 않는 이유: 필수 체크가 '대기'로 남아 머지가 영원히 잠기는 함정 |
| pr-size | 추가+삭제 줄 수가 300 초과면 실패 | DoD ② — 리뷰 가능한 크기 강제. size:exempt 라벨은 PO 승인 하의 예외 통로 |
| server-test | /server·/admin-web·/batch 변경 시 설치→빌드→테스트 | 배포 단위 ②(서버 계열)의 머지 게이트 |
| ios-build | /ios 변경 시 서명 없이 컴파일 확인 | 배포 단위 ①(앱)의 머지 게이트. 서명은 CI 시크릿 범위라 검증에서 제외 |
| secret-scan | 전체 이력에서 시크릿 패턴 탐지 | DoD ⑥ — 키 유출은 되돌릴 수 없는 실패(N-06) |
| gate | 위 결과를 종합해 하나라도 실패면 잠금 | 브랜치 보호에 등록하는 필수 체크는 이것 하나. '건너뜀'은 해당 없음으로 통과 |

## 이 파이프라인이 잡지 못하는 결함 (모범 답안 3+1)

1. 테스트가 요구를 잘못 대변하는 경우 — AC와 무관한 테스트가 통과해도 초록불이다. 잡는 것: 리뷰(AC 대조)와 ⅩⅡ장 테스트 설계.
2. 작성자가 코드를 이해하지 못한 경우 — 도구는 이해를 측정하지 못한다. 잡는 것: 리뷰의 설명 질문(DoD ③)과 PR의 '이해하지 못한 부분' 기재(DoD ④).
3. 실제 사용성·접근성 결함 — VoiceOver 완주(N-01)는 자동 검사 한계 밖. 잡는 것: DoD의 사람 검증 항목과 복지관 테스트.
4. 기록되지 않은 설계 변경 — 코드는 바뀌었는데 ADR이 없는 경우. 잡는 것: 리뷰 절차(DoD ⑤).

## 리허설 절차 (실습 8 ⑤)

더미 이슈 1건으로: 브랜치 생성 → 일부러 실패하는 테스트 커밋 → PR → gate 빨간불·머지 잠김 확인(캡처) → 수정 푸시 → 자동 재검증·초록불 → Squash 머지 → 이슈 자동 닫힘·보드 Done 이동 확인.
