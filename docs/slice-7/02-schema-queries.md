# 02 스키마·대표 질의 기록 (Ⅹ장 재료)

3단계에서 실제로 올린 스키마와 `psql`로 돌린 대표 질의·결과·EXPLAIN. 출력은 실행 결과 그대로이며 지면용으로 표 테두리만 정리했다(발췌).

## 셋업 (실행 명령)

```bash
createdb innermap_dev
cd server && npm install node-pg-migrate pg
export DATABASE_URL="postgres://<user>@localhost:5432/innermap_dev"
npm run migrate up      # migrations/1785128116857_initial-schema.js
npm run seed            # seed/seed.sql → 19건 + 별칭 16개
```

카운트 확인: `buildings=19`, `aliases=16`, `published=19`, 별칭 없는 건물 3건(창조A/B/C관).

## 대표 질의 (현재 위치 = 공학관E동 37.339713, 126.735044)

### Q1 이름 부분일치 '공학' → 거리순 (발췌)
```
   name    | dist_m
-----------+--------
 공학관E동 |    0.0
 공학관P동 |   54.7
 공학관G동 |   66.9
 공학관D동 |   79.6
 공학관C동 |   99.1
 공학관B동 |  169.7
 공학관A동 |  206.4
(7개 행)
```
거리 정렬(하버사인)이 의도대로 동작. 밴드가 아니라 거리순 최대 10(여기선 7건).

### Q2 별칭만 매칭 '도서관' (이름엔 없음) → matched_alias
```
    name    | matched_alias | dist_m
------------+---------------+--------
 종합교육관 | 도서관        |  135.3
```
이름 ∪ 별칭 합집합 검색과 `matched_alias`(LATERAL) 동작 확인. '도서관'은 종합교육관의 저자 확인 별칭.

### Q3 한 글자 '공' (경계) → 7건 · Q4 없음 '없는건물' → 0건
1자 질의도 동작(결과는 10건 상한으로 방어). 0건은 앱에서 `reason_code:"NO_MATCH"`로 안내.

### Q5 게시 필터 (R-12b) — 트랜잭션으로 검증, 롤백
`공학관A동`을 `draft`로 바꾸면 '공학' 결과가 7 → 6건으로 줄어 게시 상태 필터가 실제로 작동함을 확인(변경은 ROLLBACK).

## EXPLAIN — pg_trgm GIN 인덱스가 실제로 쓰이는가

여기서 **설계 허점이 드러났다.** 시드 규모(19행)에서 기본 플래너는 trigram 인덱스를 **쓰지 않는다.**

| 상황 | 플랜 | 비고 |
|---|---|---|
| 기본, `'%공학관%'`(3글자) | **Seq Scan** (cost 14.38) | 19행에선 순차 스캔이 더 싸서 인덱스 무시 |
| `enable_seqscan=off`, `'%공학관%'` | Bitmap Index Scan on `building_name_trgm`, 인덱스가 8건으로 좁힘 | **3글자 이상이면 인덱스가 유효** |
| `off`, `'%공학%'`(2글자) | 인덱스 스캔이나 rows=20(**전체**) recheck로 12 제거, cost 3550 | 2글자는 온전한 trigram이 없어 못 좁힘 |
| `off`, `'%공%'`(1글자) | 동일하게 전체 스캔 | 1글자도 못 좁힘 |

읽을 것 둘.
1. **19행에선 GIN 인덱스가 과임이다.** 플래너가 순차 스캔을 택한다. ADR-007에 적어 둔 "운영 척도 대비 인덱스 설계"라는 표기가 실측으로 확인됐다 — 교재는 이 사실을 숨기지 않는다.
2. **trigram은 3글자 미만 패턴을 가속하지 못한다.** 온전한 3-gram이 없어 인덱스가 전 범위를 훑는다. 한글 2·1글자 질의(예: '공학', '공')는 인덱스 이득이 없다. 정밀도·재현성의 대규모 검증은 남는 숙제(ADR-007 미검증 항목).
