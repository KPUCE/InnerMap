# 05 프롬프트 로그 — 무엇을 어느 수준으로 위임했고 왜 (Ⅺ장 재료)

지시서 §6이 "가장 자주 빠뜨리는 파일"이라 경고한 것. 위임할 때 그 자리에서 적는다.

주의: **L1~L4 위임 수준의 정의가 저장소에 없다**(교재 용어집 소관). 아래 수준 표기는 잠정이며 저자가 교재 정의와 대조해 확정해야 한다. 여기서는 "사람이 얼마나 판단·검증을 쥐고 있었나"를 기준으로 상대적으로 표기한다.

| # | 작업 | 위임 정도(잠정) | 왜 그렇게 했나 | 사람의 검증 |
|---|---|---|---|---|
| 1 | 0단계 현황 파악(파일 읽기·요약) | 높음 — AI가 읽고 요약 | 사실 수집은 기계적, 위임 이득이 큼 | 저자가 요약 대조 |
| 2 | 로컬 환경 설치(brew install 등) | 높음(단, sudo 구간은 사람) | 반복적 설치는 AI 실행이 빠름. Homebrew 부트스트랩은 암호 필요라 사람이 실행 | 버전·PG 기동 확인 |
| 3 | 시드 데이터·별칭 결정 | 낮음 — AI는 선택지만 | 실명 데이터·통칭은 저자 지식. 임의 결정 금지(§2) | 저자가 건물·별칭 직접 확정 |
| 4 | ADR-007 두 결정(pg_trgm·하버사인) | 중 — AI 권고 → 저자 승인 | 기술 트레이드오프는 AI가 정리, 채택은 저자("권고대로") | 저자 승인 |
| 5 | 2단계 설계 문서(ERD·OpenAPI·시퀀스·ADR·노트) 초안 | 높음 — AI 생성 | 형식화·문서화는 위임 이득이 큼 | 저자 검토 관문(2단계 confirm) 예정 |

| 6 | 3단계 마이그레이션·시드 작성/적용, psql 질의 | 높음 — AI 실행 | 스키마는 2단계 확정안의 기계적 구현. 단 도구 선택(node-pg-migrate)은 저자 승인 후 | EXPLAIN 실측이 검증 역할(02 파일) |
| 7 | 4단계 CI에 postgres 서비스 추가 | 중 — 저자가 A안 선택 후 AI 수정 | 게이트 워크플로우는 교재 참조 파일 — 수정 여부 자체를 저자가 결정(A/B 선택지 제시) | 저자 A안 승인 |
| 8 | 4단계 테스트 작성(구현 전 RED) | 높음 — AI 작성 | 테스트 목록은 AC+OpenAPI 명세에서 도출(정상 5·경계 4·오류 6). 구현 없는 상태로 실행해 RED 확인 | 03-red.txt로 실패 확인 |
| 9 | 5단계 서버 구현(app.js·server.js) | 높음 — AI 작성 | 완료 조건이 테스트 15개로 이미 고정돼 있어 위임 위험이 낮음 — 테스트가 검증을 대신함 | 04-green.txt 17/17 통과(첫 실행) |

교재 논점: 3번처럼 **판단을 사람이 쥔 위임**과 5번처럼 **생성을 통째로 넘긴 위임**이 한 슬라이스 안에 공존한다. 무엇을 넘기고 무엇을 쥘지의 경계가 이 표에 드러난다.
