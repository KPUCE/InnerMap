# 01 설계 노트 — 고민한 대안과 기각 이유 (Ⅹ장 재료)

지시서 §6 증거 파일. 설계 중 실제로 오간 대안과 왜 접었는지를 남긴다. 결과만 깔끔히 남기면 이 작업은 실패다.

## 시드 좌표 — 가정 좌표 → OSM 실측으로 대체
- AI가 처음 캠퍼스 배치를 눈대중한 '가정' 상대 좌표 21건을 제안했다.
- 기각: 저자가 OSM(Overpass)에서 실측 좌표 21건(ODbL)을 확보. 가정 좌표는 교재 정직성상 "(가정)" 표기가 필요하고, 실데이터가 있으면 불필요하다. → `seed-buildings.md`가 원본이 됨.
- 교재 논점: "AI가 만든 그럴듯한 좌표"와 "출처 있는 실데이터"의 차이, 그리고 ADR-003(공공데이터)과 개발 시드(OSM)의 출처 불일치를 정직하게 밝히는 문제.

## 장소 범위 — 출입구·운동시설 포함안 폐기
- AI가 출입구(정문·후문)·운동시설(운동장 등)까지 넣는 "장소(POI)+종류" 모델을 제안했다.
- 기각: OSM 시드엔 그런 이름 항목이 없어 무의미해짐. 주변 2건(시흥종합버스터미널·609아파트)은 저자가 검색 대상에서 제외. → 검색 대상 19건(전부 캠퍼스 건물).

## 별칭 출처 — 규칙 생성 vs 저자 확인
- 후보: (a) 저자 확인 손입력, (b) 규칙 생성('공학관A동'→'A동','공A'), (c) #12로 제외.
- 결정: (a) 저자 확인. 공학관도 규칙형('공A' 등)을 접고 단일 'X동'만. 실사용례가 검색 품질의 핵심이라 저자 판단을 원천으로.

## 텍스트 매칭 — ILIKE+일반 인덱스는 무효
- "ILIKE + 인덱스"를 지시서가 후보로 들었으나, `ILIKE '%q%'`는 선행 와일드카드라 일반 btree 인덱스를 못 쓴다. 부분일치를 인덱싱하는 표준은 trigram GIN.
- 결정: `pg_trgm` GIN 채택(ADR-007). 대안 'ILIKE 순차 스캔'은 19건엔 충분하나 인덱싱 논점을 못 보여줘 기각.

## 거리 정렬 — PostGIS vs 하버사인
- PostGIS geography+GiST는 정석이나 이 척도(19건, 캠퍼스 442×402m)엔 과임이고 두 번째 확장 의존을 늘린다.
- 결정: lat/lng+하버사인(ADR-007).

## 질의 최소 길이 — 1자 허용
- 후보: 2자 이상 강제 vs 1자 허용.
- 결정: 1자 허용(단음절 '공'도 의미 있음, 결과는 10건 상한으로 방어). 빈/공백만 → 400 `EMPTY_QUERY`. '한 글자 질의'는 오류가 아니라 경계 케이스로 4단계 테스트에 포함.

## 범위 정정 — 밴드·외 N개는 #7 아님
- 지시서 서술과 seed 밀집도 분석이 '밴드별 5개 상한/외 N개'를 언급하나, #7 AC엔 없다(브리핑 E2, 제외). 검색 API는 '거리순 최대 10'으로 한정. 밀집도 데이터는 거리 정렬·10건 상한 시험용으로 여전히 유효.

## 미해결/미검증 (정직한 무지)
- 한글 완성형 음절의 `pg_trgm` trigram 정밀도·재현성 — 3단계 실제 질의로 검증 예정. 현재 미검증.
